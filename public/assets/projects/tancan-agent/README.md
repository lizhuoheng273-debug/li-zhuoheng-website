# 谈参 Agent（FiT 智能谈参 Copilot）

> 一个面向腾讯金融科技（FiT）高管谈参场景的 AI Copilot：自主完成"需求拆解 → 多源检索 → 多视角推演 → 草稿撰写 → 双盲评分 → 风格润色"的全流程，把原本依赖资深员工数天的谈参撰写压缩至小时级，并形成可沉淀、可复用的知识资产与评分标准。

## 项目背景

FiT 谈参（高管对外沟通材料，如圆桌发言、监管拜访、媒体专访）长期面临三道难题：**撰写门槛高**（需要同时懂业务、合规、沟通策略）、**质量参差**（不同作者产出差异大，难以标准化）、**经验难沉淀**（优质谈参散落在个人手中，新人复用成本高）。本项目用「Agent + 工具 + 评分 + 知识库」的整体方案，把谈参撰写从"个人手艺"重塑为可被 AI 协作、可被评分对齐、可被组织复用的工作流。

## 核心能力

| 能力 | 说明 |
|---|---|
| 端到端撰写 | 从需求确认、提纲对齐，到多源信息搜集（知识库 / KM / iWiki / 外部网站）、多视角头脑风暴、N 稿迭代，一条龙完成 |
| 双盲评分 | 自研五维度（观点主题 30% / 逻辑结构 30% / 论据材料 15% / 信息增量 15% / 受众意识 10%）双 AI 独立评分 + 三评仲裁 |
| 风格润色 | 按场景模版（圆桌/演讲/采访/监管拜访/合作拜访/内部分享）调整样式与语言风格，并支持自定义风格画像 |
| 结构化知识库 | 1,907 条带 13 维元数据的结构化切片 + 三级知识图谱，支持多维筛选与关联分析 |
| 跨平台部署 | 同一套能力同时支持 Web 网站与 MCP 协议，可被 Claude Code、WorkBuddy、内网龙虾等任意 Agent 平台消费 |

avatar-chat 网站提供三个核心 Tab：**谈参 Agent**（撰写主入口）、**风格润色**（自定义风格画像）、**知识库管理**（管理 1,907 条切片与图谱）。零配置即开即用，内网用户直接打开网址即可开始对话。

## 谈参工作流

整体工作流分三大模块——**"初稿撰写 → 评分修改 → 风格润色"**——每个模块都由 Agent 自主规划工具调用，业务人员只需在关键节点确认方向。

![谈参工作流总览](谈参Agent_项目介绍_imgs/img-workflow.png)

- **初稿撰写**：需求理解 → 草拟提纲（场景模版选择）→ 信息搜集与研究（知识库 + KM + iWiki + 外部网站 + 内部顾问 + 红/蓝/绿/黄四视角头脑风暴）→ N 稿撰写与迭代
- **评分修改**：双 AI 五路盲评（观点/逻辑/论据/信息增量/受众）→ 分差仲裁 → 输出详细修改建议 → 反馈到下一轮撰写
- **风格润色**：预设风格 + 自定义风格学习 → 要点式/逐字稿样式调整 → 终稿交付

> 设计理念：**充分发挥模型智能，减少框架束缚**。Agent 在每个节点都拥有「自主决定调哪个工具、调几次」的自由度，同时在关键确认点（如提纲方向）要求人类参与，避免跑偏。

## 评分体系

评分是谈参 Agent 的"质量锚"。采用**0-3 分四档 + 五维度加权 + 双评 + 三评仲裁**：

![评分分布表](谈参Agent_项目介绍_imgs/img-scoring-table.png)

- **总分公式**：`总分 = (观点分/3 × 0.30 + 逻辑分/3 × 0.30 + 论据分/3 × 0.15 + 信息分/3 × 0.15 + 受众分/3 × 0.10) × 10`
- **评级标准**：≥8 优秀（占比 <10%）/ ≥6 通过（~35%）/ <6 待改进（~55%）
- **仲裁机制**：两模型独立评分取中位数，**分差 ≥1.5 时触发第三模型仲裁，最终取中位数**，确保评分稳定性
- **测评集**：从历史谈参中筛选 12 篇覆盖不同场景与质量水平的代表性样本，经人工标注后作为评分模型的**锚定基准**（Anchored Scoring），避免模型打分漂移

## 部署形态

项目同时提供两种部署形态，让公司内部员工灵活配置使用：

| 形态 | 技术栈 | 适用场景 |
|---|---|---|
| **Web 网站**（avatar-chat） | React 前端 + Flask 后端，GLM-5.1 驱动 Agent Loop，SSE 流式输出 | 内部团队日常使用、零配置上手 |
| **MCP 服务端**（tancan-mcp-server） | Python + FastMCP（5 个工具：kb_search / iwiki_search / km_search / request_review / submit_draft），Streamable HTTP + stateless=True | Claude Code、WorkBuddy、内网龙虾等任意支持 MCP 的 Agent 平台直接调用 |

## 技术架构

项目按「模型决策 → 知识供给 → 质量校验 → 能力交付 → 工程支撑」五层组织：

**1. 模型决策层 —— Agent Loop + Function Calling**

主模型 GLM-5.1 通过 Function Calling 自主规划工具调用，共 17 个工具（kb_search / iwiki_search / km_search / draft_write / red_blue_green / notepad 等）按需调度。工具结果以 `role: "tool"` 消息回灌模型，形成"规划 → 调用 → 反馈 → 再规划"的闭环；用户仅在提纲确认等关键节点介入。

**2. 知识供给层 —— 混合检索 RAG + 知识库**

知识库沉淀 1,907 条带 13 维元数据的结构化切片，并自动归纳为三级知识图谱（战略要点 / 战术方向 / 观点支撑）。检索采用三阶段方案：向量（qwen3-embedding-8b，语义匹配）与 BM25（jieba，精确词匹配）双路各召回 top-K×3 → 加权 RRF 融合（向量 0.6 / 关键词 0.4，k=60）→ qwen3-reranker-4b 精排 + 阈值过滤，最终取 top-30 拼装带引用映射（citation_map）的 context 回灌模型。

**3. 质量校验层 —— 锚定评分体系**

五维度（观点主题 30% / 逻辑结构 30% / 论据材料 15% / 信息增量 15% / 受众意识 10%）0-3 分四档评分。每维度配 3 个标杆样例做锚定，防止模型打分漂移；双 AI 独立评分取中位数，分差 ≥1.5 时触发第三模型仲裁；配套 12 篇人工标注测评集，保证评分稳定可比。

**4. 能力交付层 —— 工具封装与双部署**

同一套能力以两种形态交付：Web 网站（React + Flask，SSE 流式输出）供内部团队零配置使用；FastMCP 服务端（5 个工具：kb_search / iwiki_search / km_search / request_review / submit_draft，Streamable HTTP + stateless）供 Claude Code、WorkBuddy、内网龙虾等任意支持 MCP 的 Agent 平台直接调用。

**5. 工程支撑 —— 记忆与上下文管理**

Agent 维护四层记忆结构（agent_context 上下文字典 / notepad 手记 / citation_map 引用映射 / draft_history 版本管理），支撑多轮长对话。上下文压缩仅针对 tool 消息（保留最近 4 条 + 头尾截断 + LLM 摘要兜底），对话与草稿由前端 localStorage 按 sessionId 隔离持久化，多会话互不串扰。
